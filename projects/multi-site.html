Multi-Site Enterprise Campus & Data Center Network

A production-inspired learning topology connecting an HQ campus, a data center, and a simulated WAN/Internet edge. The network was implemented and tested in Cisco Packet Tracer; it is not a physically deployed production network.

Project Overview

The lab models three routed domains: a headquarters campus for Sales and Engineering, a data center for Web and Database servers, and a WAN/Internet edge. Layer 3 switches provide local VLAN gateways, while a central router connects the sites and a simulated ISP.

3 domainsHQ, data center, WAN/edge
5 VLAN IDs10, 20, 40, 50, and 99
172.16.0.0/16Host and server address block

Network Topology

The HQ and data center cores route their local VLANs and connect to a central WAN router using routed point-to-point links. The WAN router forwards toward an ISP edge, where a loopback provides a deterministic external test target.

Network domains

  • Headquarters: access/core hierarchy with Sales (VLAN 10) and Engineering (VLAN 20).
  • Data center: dedicated core and access switching for Web (VLAN 40) and Database (VLAN 50) server networks.
  • WAN and edge: central WAN router, ISP edge router, routed point-to-point links, and Loopback0 at 8.8.8.8/32.
  • Management planning: VLAN 99 is used as the custom native VLAN on documented trunks and appears in some allowed-VLAN lists. The supplied configurations do not show a VLAN 99 SVI or verified switch-management reachability, so a separate management plane is not claimed as complete.

Architectural Decisions

  1. SVIs for local routing: HQ and data center Layer 3 switches provide VLAN gateways, keeping inter-VLAN routing local rather than sending it through a router-on-a-stick link.
  2. VLSM for address allocation: Separate prefix lengths fit the documented Sales, Engineering, Web, and Database subnets without assigning each a full /24.
  3. /30 point-to-point networks: Each routed interconnect has two usable endpoint addresses and remains distinct from host VLANs.
  4. Routed core-to-WAN links: Core switch ports facing the WAN router use no switchport, creating Layer 3 boundaries between campus switching and the WAN.
  5. Custom native VLAN: Trunks specify VLAN 99 instead of the default VLAN 1. This is a configuration choice, not by itself proof of VLAN isolation or a complete trunk-security control.
  6. ISP loopback test target: Loopback0 at 8.8.8.8/32 gives the simulation a stable endpoint for checking default-route forwarding; it is not a connection to the public Internet.

Deployment Instructions

  1. Clone the project repository.
  2. Open topologies/MultiSite_Enterprise.pkt in Cisco Packet Tracer 8.0 or later.
  3. Compare device running configurations with the text files under config/.
  4. From PC1-Sales1, test the documented routes with ping 8.8.8.8 or tracert 8.8.8.8.
